Big picture

Why organize code?

IAN 601 · Module 6

Small scripts are fine at the beginning. But analytics projects often grow into repeated steps, helper functions, reports, and models.

  • Without organization: code becomes hard to find and easy to break.
  • With organization: related work has a clear home.
  • For teams: names and structure make the work easier to review.
  • For future you: organized code is easier to reuse next month.

import mathLoad the built-in math module.

Simple idea: a module is like a toolbox. You import the toolbox, then use the tools inside it.

Cleaner import names

Aliases and selective imports

IAN 601 · Module 6

Aliases give a module a shorter name. Selective imports bring in only the part you need.

import statistics as statsUse stats as a shorter name.
from datetime import dateImport only date from the datetime module.
Use aliases when they improve readability. Do not create confusing nicknames just to make code shorter.
Import styleExampleWhen useful
Whole moduleimport mathYou need several tools from the module.
Aliasimport pandas as pdThe alias is common and easy to recognize.
Selectivefrom math import sqrtYou only need one specific function.

Project structure

Create your own module

IAN 601 · Module 6

A module can be a file that you write yourself. Put repeated helper functions in one file, then import them into a main script.

project/ ├── main.py └── calculations.py
  • calculations.py: keeps reusable formulas.
  • main.py: runs the analysis and uses the formulas.
  • Benefit: the main file stays short and easier to read.
calculations.pydef calculate_profit(...): return ...
↓ import
main.pyfrom calculations import calculate_profit print(calculate_profit(...))
Beginner idea: when a script has many useful functions, move related functions into a module file.

Folder-level organization

What is a package?

IAN 601 · Module 6

A package is a folder that groups related modules together.

  • A module is usually one .py file.
  • A package is a folder of related modules.
  • Large analytics libraries are packages.
  • Packages help keep a project from becoming one very long file.
In this beginner module, the main goal is to recognize the idea. You do not need to build a complex package yet.

Important vocabulary

Module, package, and library

IAN 601 · Module 6

These words are related, but they are not exactly the same. This distinction helps when you start using tools like NumPy and Pandas.

Simple rule: module = file, package = folder, library = reusable collection of tools.
TermSimple meaningExample
ModuleOne Python file with reusable code.math, calculations.py
PackageA folder that groups related modules.analytics/
LibraryA larger reusable collection of packages and modules.NumPy, Pandas

Module

Useful when one file has related functions.

Package

Useful when a project has several related files.

Library

Useful when many people reuse the same tools.

Methods and self

IAN 601 · Module 6

A method is a function that belongs to a class. It usually uses self to access the object’s own data.

  • Attribute: data stored in an object.
  • Method: action the object can perform.
  • self: the current object.

Practical decision guide

Function, dictionary, or class?

IAN 601 · Module 6

Beginners often ask whether they should use a function, dictionary, or class. Use the simplest structure that clearly matches the job.

Use a function

When you mainly need to perform one reusable task.

def get_profit(sales, costs): return sales - costs

Use a dictionary

When you mainly need to store related values.

product = { "name": "Laptop", "price": 900 }

Use a class

When data and behavior belong together.

class Product: def sale_price(self, rate): return self.price * (1 - rate)
Beginner rule: start simple. Move to a class only when one concept has both stored data and repeated actions.

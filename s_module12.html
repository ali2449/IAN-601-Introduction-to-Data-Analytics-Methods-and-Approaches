Drop, fill, preserve, or investigate?

Decide how to handle missing values

IAN 601 · Module 12

Drop

Reasonable when the row or column is unusable and enough data remains.

Fill

Use a justified value such as a median, mode, domain default, or model-based estimate.

Preserve

Sometimes missingness is meaningful and should remain visible.

Investigate

The best next step may be finding why the value is missing before changing it.

Avoid automatic cleaning. Filling every numeric column with the mean or deleting every incomplete row can introduce bias or remove useful information.

For a simple teaching example, we can fill a missing satisfaction score with the median, but only after deciding that this is reasonable for our purpose.

Convert data types safely

IAN 601 · Module 12

Numbers and dates often arrive as text. Use conversion functions that make invalid values visible instead of crashing or silently producing incorrect analysis.

  • pd.to_datetime(..., errors="coerce")

Standardize case, spacing, and labels

Clean text categories

IAN 601 · Module 12

Small text differences can create fake categories. For example, Web, web, and web may represent the same channel.

  1. Remove extra spaces with .str.strip().
  2. Standardize case with .str.title() or another rule.
  3. Map known variants when spelling differs.
Check before and after. Use value_counts() to confirm that categories were combined as expected.

Some errors are valid Python values

Validate ranges and business rules

IAN 601 · Module 12

A value can have the correct data type and still be impossible or invalid for the project.

  • A negative order amount may violate a business rule.
  • A satisfaction score of 9 is invalid if the scale is 1 through 5.
  • A future date might be invalid for a historical dataset.
Domain rules catch problems that dtypes cannot. These rules should come from the meaning of the data, not only from statistics.

Outliers are questions, not automatic deletions

IAN 601 · Module 12

An outlier is an observation that looks unusual compared with the rest of the data. It may be an error, but it may also be a real and important event.

Possible errorA misplaced decimal point
Rare but realA very large legitimate order
Different processA wholesale order mixed with retail orders
Detectflag unusual values
then
Investigatecheck source and context
then
Decidekeep, correct, transform, or exclude
Do not write: “I removed all outliers.” Explain how they were identified and why the chosen treatment is appropriate.

A simple statistical screening method

Flag outliers with the IQR rule

IAN 601 · Module 12

The interquartile range, or IQR, uses the middle fifty percent of the data to define lower and upper fences.

IQR = Q3 - Q1Lower fence = Q1 − 1.5 × IQR
Upper fence = Q3 + 1.5 × IQR
Remember: the IQR rule flags unusual values. It does not prove that those values are wrong.

Explore categorical variables

IAN 601 · Module 12

For categorical columns, start with frequencies. Counts tell you how many observations are in each group, while proportions make groups easier to compare.

  • value_counts() for counts
  • value_counts(normalize=True) for proportions
  • dropna=False when missing values should stay visible
EDA question: Are some categories unexpectedly rare, dominant, or missing?

Center, spread, and range

Explore numeric variables

IAN 601 · Module 12

For numeric columns, EDA usually begins with summary statistics that describe the center and spread of the values.

  • mean and median describe center
  • standard deviation describes spread
  • min and max reveal range
  • quartiles help identify skew and unusual values
Compare mean and median. A large difference can be a clue that the distribution is skewed or contains extreme values.

A clean dataset should be reproducible

Document your cleaning decisions

IAN 601 · Module 12

Good cleaning is not only about the final DataFrame. You should be able to explain what changed and why.

  • What issue was found?
  • Which rows or columns were affected?
  • What rule was applied?
  • How many values changed?
  • Why was that decision reasonable?
IssueChannel labels had extra spaces and inconsistent case.
ActionApplied strip and title-case standardization.
CheckCompared value counts before and after.
ReasonValues represented the same business categories.
In a real project: keep cleaning code in a notebook, script, or pipeline rather than editing the source file manually.

Check the data after cleaning

  4. Review category values.
